# Castle Frenzy — Unity 6000.3.26f1 port

A full port of the C++ game (`Src/`, Gameloft's Irrlicht fork) to Unity, plus Unity editor versions of the
project's two authoring tools (`Tools/AuroraMX` sprite editor and `Tools/LevelEditor`).

The port is a straight C++ → C# translation of the game code on top of a small Irrlicht-compatible layer, so
gameplay, menus, timing, randomization rules and data formats behave like the original. The game reads the same
data the C++ build uses (sprite YAML, BDAE scenes, XML levels/config, audio packs, string tables) from
`Assets/StreamingAssets/GameData`.

## Open, play, build

- Open the `Unity/` folder with Unity **6000.3.26f1** (Linux/Windows editor; Built-in Render Pipeline).
- Press Play in `Assets/CastleFrenzy/Scenes/Main.unity` (any scene works: `GameMain` bootstraps itself).
  Mouse = touch, right button = second finger. F2/F3 halve/double game speed, F11 toggles full screen.
  Left/Right arrows tilt the "accelerometer" (rolling boulder / tornado), like the original desktop emulation;
  phones use the real accelerometer.
- Menu **Castle Frenzy ▸ Build ▸ Linux Player / Windows Player / Android APK**, or in batch mode:

  ```bash
  Unity -batchmode -nographics -quit -projectPath Unity \
        -executeMethod CastleFrenzy.EditorTools.BuildScript.BuildLinux -cf-output Builds/Linux/CastleFrenzy.x86_64
  ```

  `BuildWindows` and `BuildAndroid` work the same way (the Windows build needs the Windows Build Support
  module). Android builds are IL2CPP/ARM64 (add `-cf-android-arch arm64,x86_64` for emulators/Chrome OS); on
  first launch the APK copies GameData to persistent storage using `GameData/manifest.txt`, which every build
  regenerates.
- Saves (profile, achievements, scores) go to `Application.persistentDataPath/castle-frenzy/`.

## Editor tools (menu **Castle Frenzy**)

Both tools draw their previews with the game's own renderer (sprites, fonts, skinned/animated BDAE models),
so what you see is what the game shows. Previews pause while the game runs in Play mode.

### AuroraMX Sprite Editor

Equivalent of `Tools/AuroraMX` for the sprite YAML format (`Data/Sprites/**/*.yaml`).

- **File ▸ Open** any sprite; **Save** (Ctrl+S) writes `StreamingAssets/GameData/Sprites/…` and keeps the
  other copies identical (`Build/bin/Sprites/…` and `Data/Sprites/…`), then regenerates the C# sprite ID
  constants. Overwritten files are backed up under `.unity-editor/backups/`.
- **Modules**: insert/clone/delete/reorder, edit ids/rectangles/images (transparent key, alpha mask). The atlas
  view selects modules, drags them, and draws new ones (“Draw module on atlas”). Wheel zooms.
- **Frames**: parts (module or hyper-frame, offsets, FLIP_X/FLIP_Y/ROT_90), layer order, collision rectangles.
  Drag parts in the preview; wheel zooms, middle/Alt-drag pans, **Fit** frames the bounds.
- **Animations**: steps (frame, time in 25 Hz ticks, offsets, flags); play/pause (Space), step, loop, onion skin.
- **Source**: edit the YAML text directly and apply it.
- Undo/Redo (Ctrl+Z/Ctrl+Y) for all structured edits; **Validate** checks the rules the game's loader enforces.

### Level Editor

Equivalent of `Tools/LevelEditor` for `Levels/*.xml`.

- **Levels / days**: create, delete, reorder levels (the last level is always Endless); create, copy, paste,
  cut and reorder days. Files are renumbered on save.
- **Waves**: day end time, challenge, endless segment difficulty; waves with packed spawning, start, duration,
  repeat interval/count; variants (intro camera) with enemy types and min/max counts. The timeline shows every
  repeat: left-drag = start, right-drag = duration, middle-drag = repeat spacing, wheel = repeat count.
- **Weapons**: per-level starting levels (None/1/2/3 ↔ −1…2), shop availability, spell and “spell bought”.
- **Models**: every model definition in `config/models.xml`, with clip list, play/pause, speed, scrub, orbit
  (left drag), pan (right drag) and zoom (wheel).
- **Spawns**: the day's randomized spawn list per difficulty (re-roll); while the game is playing, the live
  spawn list with spawned/next/future state, extra spawns, Pause/Resume and “DIE!” (kill all units).
- **▶ Play day / ▶ Play level** saves and enters Play mode directly in that level/day (difficulty and
  “Skip cutscene” in the toolbar).
- Saving only rewrites changed files (UTF-16, same layout as the shipped XML — unchanged data re-saves byte for
  byte), mirrors them into `Build/bin/Levels`, and removes files of deleted days/levels.

### Game data commands

- **Game Data ▸ Sync From Build|bin** copies changed files from `Build/bin` into `StreamingAssets/GameData`
  (after editing data with the C++ tool chain).
- **Game Data ▸ Regenerate Sprite IDs** rebuilds `Scripts/Autogenerated/Ids_{Menu,Ingame,Fonts}.cs` from the
  sprite YAML following `Data/Sprites/Sprites.sprcmd` (AuroraMX's `ExportFramesID/ExportAnimsID` naming).
  String and sound IDs: `python3 tools/unity/gen_ids.py` (`--check` to verify). String IDs come from
  `Data/Strings/fortress_defender_strings.xls` (sheet_ROWID in workbook order), sound IDs from the shipped
  `audio_Music.pack` + `audio_SFX.pack` (archive order, as the game registers them). No C++ headers are read.

## Code layout (`Assets/CastleFrenzy`)

| Folder | Contents |
| --- | --- |
| `Scripts/Engine` | Irrlicht-style math, scene graph, BDAE loader + Collada animator, renderer (`Gfx`: command buffer, 480×320 virtual screen, GPU skinning), textures/files, XML, attributes/config/profile, sound packs |
| `Scripts/Core` | `GameMain` (Unity entry), `CApplication`, state machine, touch pad/elements, launch options, automation, Android data installer |
| `Scripts/Sprites`, `Scripts/Fonts` | ASprite (YAML sprites), sprite instances, fonts |
| `Scripts/Particles` | particle system scene node, emitters/affectors, presets from `Effects/effects.xml` |
| `Scripts/Game` | playfield, units, projectiles, weapons (gate, hydra, fireball, iceball, griffin, spells), gestures, level data, achievements |
| `Scripts/VisualControls`, `Scripts/Menus`, `Scripts/GameStates` | UI controls, every menu, splash/menu/level/shop/cheat states |
| `Resources/Shaders` | `CF_Sprite` (2D/billboards) and `CF_Mesh` (lit/skinned meshes) reproducing the fork's GL material renderers |
| `Editor` | AuroraMX, Level Editor, shared preview renderer and data tools, build script, self-tests |

Notes on fidelity: enums are `int` constants and C++ destructors are explicit `Dispose()` calls (touch elements
unregister there). The fork's GL blend modes are reproduced (`trans_add` is `SrcAlpha, One`;
`trans_vertex_alpha` takes alpha from vertices). The render-to-texture background path is disabled
(`CGameConfig.DisableRTT`), which the original also supports.

## Automation and tests

Player command line options (also used by the screenshots in development):

| Option | Effect |
| --- | --- |
| `-cf-level N -cf-day D -cf-difficulty 0..2`, `-cf-endless` | start directly in a level/day |
| `-cf-skip-cutscene` | skip the camera intro |
| `-cf-all-weapons`, `-cf-no-cooldown` | the game's cheat switches |
| `-cf-spell boulder\|lightning\|ghost\|tornado` | spell given by `-cf-all-weapons` (default tornado) |
| `-cf-script file` | scripted input: `<frame> down/move/up/tap x y [finger]`, `<frame> shot file.png`, `<frame> quit` |
| `-cf-frames N -cf-screenshot file.png` | run N frames, save a screenshot, quit |
| `-cf-timescale X`, `-cf-autokill` | test hooks: faster game time, kill walking units |
| `-cf-quit-on-result` | log `[CastleFrenzy] Result level L day D: victory/defeat` when the day ends, then quit |
| `-cf-autoplay` | test bot that defends through the touch input (throws units, smashes warlocks/elves/skeletons) |
| `-cf-fast` | uncapped frame rate on desktop, display refresh rate on phones (automation runs use a fixed 1/60 s step, so results are unchanged; keep `-cf-timescale` at 1 for the bot, which loses days at 2×) |

`python3 tools/unity/play_all_days.py` plays every campaign day and endless segment with the bot (one player per
day, `-j` at a time) and exits non-zero if a day is lost, never finishes, or logs an exception; `--autokill` is a
faster load/finish-only check.
| `-cf-save-dir dir`, `-cf-data dir` | alternative save/data folders |
| `-cf-test renderer` | renderer self-test scene |

On Android the same options go in the `unity` intent extra, and results appear in `adb logcat -s Unity`:

```bash
adb shell am start -S -n com.castlefrenzy.game/com.unity3d.player.UnityPlayerGameActivity \
    -e unity "'-cf-level 9 -cf-day 12 -cf-skip-cutscene -cf-autokill -cf-timescale 6 -cf-quit-on-result'"
```

Editor checks (batch mode):

```bash
# sprite YAML round trip, ID regeneration, level XML round trip, preview renders
Unity -batchmode -projectPath Unity -executeMethod CastleFrenzy.EditorTools.EditorToolsSelfTest.Run -cf-out /tmp/out
# opens both tool windows and saves screenshots of every tab (needs a desktop session)
Unity -projectPath Unity -executeMethod CastleFrenzy.EditorTools.EditorWindowShots.Run -cf-out /tmp/out
```
